# Cross-agent parity: Claude Code, Codex, Cursor, Gemini CLI

What each of the four plugin adapters (`adapters/claude`, `adapters/codex`,
`adapters/cursor`, `adapters/gemini`) does, feature by feature, and where an
agent runtime can't support a feature. The native and API adapters
(`opencode`, `pi`, `devin`) are not in this matrix.

The source of truth is [`parity.json`](parity.json). The matrix below is
generated from it by `python3 build/parity_md.py`, and
`tests/test_parity_matrix.py` checks both against the code:

- **P (present)**: at least one probe checks it in the code: a hook
  registration (event, handler, and the tools its matcher covers), a skill,
  a file, an MCP server, or a grep for the shared core call in the adapter's
  hook. Codex and Cursor register hooks and MCP servers from
  `scripts/cardinal-connect`; the test runs those writers against scratch
  files to read what they register.
- **L (limit)**: the runtime can't support it. Each limit cites a doc URL, a
  README section or a gemini-cli bundle reference, and says what the plugin
  does instead.
- **N/A**: not a parity item, with the reason.

Every hook in `adapters/claude/hooks/hooks.json` has to map to a feature
here (or to the short `_claude_internal_hooks` allowlist in `parity.json`,
with a reason), so a new Claude-only hook fails the test until someone makes
the parity decision.

The design and the history of each row are in
[`plans/cross-agent-parity.md`](plans/cross-agent-parity.md) (§2 for the
authority and privacy rules behind the turn-end and owner-input rows).

## How to add a feature

1. Add the row to `docs/parity.json`: an id, `title`, `group`, and a cell
   for all four adapters.
2. Add the probe for every `present` cell (`probes.<adapter>`, one probe or
   a list): `hook`, `skill`, `script`, `agent`, `mcp` or `grep`. Paths are
   relative to `adapters/<adapter>/`.
3. Wire every adapter, or declare `limit:<citation>` (a doc URL, a
   `<file>.md#anchor`, or a gemini-cli `chunk-*.js:<line>`) or
   `na:<reason>`. A present cell on one adapter with a missing or unknown
   cell on another fails the test.
   Optionally, `notes.<adapter>` qualifies a present cell (for example
   "notify-only"), and `outside_matrix.<opencode|pi|devin>` (`na:` or
   `limit:`) records why a native or API adapter lacks the feature.
4. Run `python3 build/parity_md.py` to regenerate the matrix below, then
   `python3 -m unittest discover -s tests -p test_parity_matrix.py`.
